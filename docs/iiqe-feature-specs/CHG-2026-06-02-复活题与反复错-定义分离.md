## 修改原因

原实现将「累计答错 >5 次」与「从已掌握复活」绑在同一持久化标记 `revived` 上，导致：

1. **从未归档、一直在待复习**的题，错到第 6 次起也被打上「复活题」角标，与考生心智（复活 = 曾掌握后又丢）不符。  
2. 列表统计「反复错」、刷题红条、标题角标三套身份在数据层打架，教研与验收难以单字段对照。

城主确认：**反复错与复活题独立，不做身份叠加**；取消产品约定「反复错 ⇒ 一定算复活题」。

## 定义对照（旧 → 新）

| 维度 | 旧定义（已废弃） | 新定义（当前） |
|------|------------------|----------------|
| **复活题** `revived` | 已掌握后再错 **或** 答错后 `wrongCount>5` 时置 `true` | **仅**已掌握后再答错时置 `true`；归档时清 `false` |
| **反复错** `repeatedWrong` | `wrongCount > 5`（计算字段） | 不变；**不得**因反复错写入 `revived` |
| **角标「复活题」** | `revived \|\| repeatedWrong` | **仅** `revived` |
| **红底栏「反复错…」** | `repeatedWrong && !canArchive` | 不变 |
| **包含关系** | 反复错 ⇒ 一定是复活题 | **无包含**；两字段独立判断 |

### 场景速查

| 场景 | `revived` | `repeatedWrong` | 角标 | 红条 |
|------|-----------|-----------------|------|------|
| 待复习内错满 6 次+，从未归档 | `false` | `true` | 无 | 有（不可归档时） |
| 已掌握后再错（刚复活，累计错≤5） | `true` | `false` | 有 | 无 |
| 已掌握后再错，且历史累计错>5 | `true` | `true` | 有 | 有（不可归档时） |

## 本期范围（In）

### 数据层

- `recordErrorBookAnswer`：答错时 `revived = revivedFromMastered ? true : Boolean(current.revived)`  
- 移除：`repeatedWrong` 触发 `revived := true`  
- 旧版迁移：不再将 legacy `repeatedWrong` 布尔映射为 `revived`

### UI 层（仅错题本 `fromErrors` 掌握进度区）

- 标题角标：条件改为 `!archived && revived`  
- 红条、绿条、灰条逻辑不变（绿优先于红）

### 文档

- `FOCO_错题本-复活题与反复错说明.md` v2026-06-03  
- `FOCO_错题本功能说明.md` §1.4、§4.3.4 关系表与 UI 表

### Out

- 列表四段灰字算法（仍只数 `repeatedWrong`）  
- 归档 / Session 门槛 / 答题记录弹窗（CHG-A / CHG-B）  
- 可选：历史 localStorage 中「仅反复错却被标 revived」的批量清洗（未做；见备注）

## 验收要点

- [ ] **未归档 + wrongCount>5**：列表「X题反复错」+1；刷题**无**「复活题」角标；不可归档时有红条  
- [ ] **已掌握后再错**：`revived=true`、回待复习；角标有；`wrongCount≤5` 时**无**红条  
- [ ] **任意入口**已掌握题再错：数据复活 + 轻提示「该题已复活回错题本」  
- [ ] **归档确认**：`revived=false`；角标消失  
- [ ] 与 `FOCO_错题本-复活题与反复错说明.md` 速查表、§3.2 一致  
- [ ] Vercel 生产与 GitHub `main` 含本变更提交

## 备注（教研 / 测试）

- **本地旧数据**：升级前若因旧规则已写入 `revived=true` 的「纯反复错」题，角标可能残留至下次归档或按新规则再次从已掌握复活；需要一键清洗可另开工单。  
- **Figma**：角标与红条条件与 CHG-A 画板一致，仅「未归档顽固错」不再出现复活角标（无需改组件，验收行为即可）。
